# Android 屏幕传输与远程操作方案（MVP）

## 1. 目标
- 在现有 RVCS 架构上新增“远程看屏 + 基础远程操作”能力。
- 第一版优先稳定可用，不追求一次覆盖所有机型/所有手势。

## 2. 范围定义
### 2.1 第一版要做（In Scope）
- 实时屏幕传输（Android -> Web 端）。
- 远程基础控制：
  - 单击
  - 滑动
  - 返回 / 主页 / 最近任务
  - 基础文本输入（可选，按机型验证后启用）
- 控制状态可见：
  - 当前是否在“屏幕推流中”
  - 当前是否“远程控制已连接”
- 审计日志：
  - 谁发起了远程控制
  - 开始/结束时间
  - 关键操作事件（开关会话）

### 2.2 第一版不做（Out of Scope）
- 多指手势（双指缩放等）。
- 完整系统级权限页面控制（支付/安全页等）。
- 录屏音频采集与回传。
- 跨端文件拖拽、剪贴板双向同步。

## 3. 技术路线
## 3.1 Android 端
- 屏幕采集：`MediaProjection + VirtualDisplay`。
- 视频推流：复用现有 LiveKit/流管理链路，新增 Screen Track。
- 远程输入：
  - 优先：`AccessibilityService.dispatchGesture`（无 Root 可量产）
  - 系统键：通过 Accessibility 全局动作（Back/Home/Recents）。
- 前台服务：
  - 增加 mediaProjection 相关前台服务能力与生命周期管理。
- 会话状态：
  - 心跳增加 screen/control 状态字段，便于前端展示。

## 3.2 后端
- 复用现有命令通道，新增命令：
  - `screen_on` / `screen_off`
  - `remote_tap` / `remote_swipe`
  - `remote_key`（back/home/recents）
- 增加设备能力字段（是否支持 screen/control）。
- 增加审计日志字段（操作者、会话 ID、来源 IP、时间）。

## 3.3 Web 端
- 设备详情页新增“屏幕会话”区域：
  - 开始/停止屏幕传输
  - 进入/退出远程控制
- 在视频画面上做坐标映射：
  - 前端坐标 -> 设备屏幕坐标
  - 适配旋转、缩放、黑边场景
- 基础操作按钮：
  - Back / Home / Recents

## 4. 关键约束与风险
- Android 版本与 ROM 差异显著，需机型白名单逐步验证。
- `MediaProjection` 授权存在系统限制，首次授权流程不可绕过。
- Accessibility 控制能力在部分页面受限（系统安全策略）。
- 屏幕推流会增加功耗与发热，需要码率/帧率策略。

## 5. 分阶段计划
## 阶段 A：POC（1-2 周）
- 单机型跑通：
  - 屏幕推流可看
  - 点击/滑动可执行
  - Back/Home/Recents 可执行
- 完成基本异常恢复（连接断开重连）。

## 阶段 B：MVP（2-4 周）
- 多机型验证（至少 2-4 款目标机型）。
- 前后端状态展示完整。
- 日志审计落地。
- 基础性能优化（帧率、码率、自适应）。

## 阶段 C：稳定化（持续）
- 长稳测试（长时间在线、温控、后台恢复）。
- 失败重试和会话保活策略细化。
- 问题机型专项适配。

## 6. 验收标准（MVP）
- 屏幕传输：可稳定持续 30 分钟不断流（目标机型集）。
- 操作延迟：点击到响应中位数可接受（按网络条件定义阈值）。
- 控制成功率：基础动作成功率 >= 95%（目标机型集）。
- 失败可恢复：断线后可自动恢复或人工一键恢复。
- 审计可追溯：会话开关、操作者、时间、设备均可查。

## 7. 建议的下一步
- 确认目标机型清单（首批 2-4 台）。
- 确认第一版是否必须包含“文本输入”。
- 确认安全策略：
  - 谁可发起远程控制
  - 是否需要二次确认
  - 会话超时时间
